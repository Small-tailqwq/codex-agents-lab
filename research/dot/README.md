# Dot

给 OpenAI Dot 用的 AGENTS。片段在 [`fragments/dot/`](../../fragments/dot)，按板块组织：

| 板块 | 片段 | 管什么 |
| --- | --- | --- |
| 沟通 | `100` 至 `140` | 对话语言、被纠正时怎么回应、犯错后不表演道歉、防御性措辞、进度汇报 |
| 行动 | `200` 至 `230` | 改动范围、卡住时先查原因、长任务怎么不断档、验证花多少时间 |
| 授权 | `300` 至 `340` | 云端无法开放完全权限时的默认边界，被自动审查拦下时怎么办 |
| 授权场景 | `350` 起 | 你给 Dot 放了哪些权、放多大的心、能接受多大损失 |
| 交付 | `400` 至 `430` | 仓库文本、界面文案、提交署名 |
| 维护 | `500` | Dot 自己更新 AGENTS.md 时的规矩，不许自己扩大授权 |

[`AGENTS.author-2026-11-18.md`](AGENTS.author-2026-11-18.md) 是作者 11-18 实际贴进 Dot 的版本，带三个自用授权场景。`tools/build.py --check` 用它校验片段库。

## 写授权场景

在[展示页](https://small-tailqwq.github.io/codex-agents-lab/#t=dot&s=6.1)上选 Dot，「放权」下面可以直接填；也可以让 `agents-composer` skill 逐项问你。每个场景写清：

- Scope：范围，哪个账号、游戏、仓库、网站。
- Granted：允许不问就做的事。
- Why：东西归谁，损失能接受多少。
- Still ask：仍需每次确认的事。
- Never：绝不做的事。

自动审查会对照这些内容检查 Dot 的操作，范围写得越具体越不容易被拦。范围内不可撤销的动作（比如游戏里的单向剧情推进）要在 Granted 里明写，并在 Why 里写清最坏结果是什么，否则审查容易把「不可逆」当成需要确认。

片段库里的三个授权场景是作者自己的：AI 自己游玩的单机游戏、网页游戏 COR3，以及专门注册给 Dot 用的 GitHub 机器人账号。这几项都完全放权，默认不选中，当作写法示例。

## 授权怎么写才算数

依据是 Codex 模型目录（`~/.codex/model_catalog.override.json`）里各模型的 `confirmation_policies`，也就是浏览器/电脑操作的确认策略。这是 Codex 的目录，Dot 运行时是否逐模型使用同一份文本没有验证过；唯一的联系是 GPT-6.2 Astra 那一版的正文直接提到了 Dot。目录里有两版策略：

| | 旧版（gpt-6.1-terra、6.2 Sol 及更早） | 新版（只有 gpt-6.2-astra） |
|---|---|---|
| 预先批准从哪来 | 用户在本次任务的请求里明确授权具体动作 | 用户请求或自定义规则；长期授权需写清动作、对象、限额 |
| 模型自己能改的内容 | 没有规定 | 只算背景，不能构成授权 |
| 改密码 | 必须由你接手 | 可以预先批准 |
| 验证码、接受服务条款、新建或扩大持久访问权限 | 每次确认，预先批准无效 | 验证码可设长期授权；非监管行业随登录或注册接受的条款不需确认 |
| 转账、永久删除、安装来源不明的软件 | 接手或每次确认 | 每次确认，自定义规则不能放开 |

2026-11-18 实测 Dot 默认主模型是 gpt-6.1-terra，按目录对应旧版：

- 旧版只承认任务请求里的授权，授权场景起的作用是让模型和自动审查少问，策略文本本身不认它。属于「可预先批准」的动作（登录、上传文件、指定收款方和金额上限的普通付款等），在任务请求里直接点名最稳。
- 旧版规定每次确认的动作写进授权场景也放不开。GitHub 机器人账号场景里「新建令牌、安装应用、OAuth 授权仍需确认」与此一致。
- 授权板块的措辞对两版都成立，不点名具体哪些动作必须接手。主模型换成 6.2 Astra 后，可以按新版考虑放开机器人账号的令牌创建和验证码。

## 6.2 变体

Dot 的 6.1 版是日常在用的版本。选 GPT-6.2 时有三处不同，都没有在 Dot 上实测：

| 片段 | 多出来的内容 | 依据 |
| --- | --- | --- |
| `110-corrections` | 只为已确认的点改代码 | Codex 6.2 对照实验（S2） |
| `310-auth-defaults` | 请求留有选择时做可逆假设并继续 | 6.2 的行为说明：意图不清时会提出下一步然后等确认 |
| `500-maintenance` | 平台把模型自己写的文字当背景，自己加的授权不起作用 | gpt-6.2-astra 的确认策略 |

中文文风和验证时长两节在 Codex 6.2 上实测已不需要，Dot 上没有测，6.2 预设里仍然带着，可以先关掉观察。

## 维护

Dot 会根据聊天自己往 AGENTS.md 里加规则。隔一段时间把它的版本拷回来对比，把有用的条目合进对应片段。
